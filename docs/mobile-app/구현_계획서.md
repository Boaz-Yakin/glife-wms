## 1. 개요 및 목표

본 계획서는 창고 현장 작업자(`INSPECTOR`)가 사용하는 모바일/PWA 재고 조사 및 실사 모듈의 구체적인 개발 절차와 산출물을 정의합니다.
현장 작업 속도(0.05초)와 데이터 무결성(원자적 트랜잭션), 한 손 조작 편의성(Thumb-Zone)을 완벽히 보장하는 것을 목표로 합니다.

---

## 2. 개발 환경 및 기술 스택

- **프레임워크**: Next.js 15 (App Router)
- **언어**: TypeScript (strict mode)
- **스타일링**: Tailwind CSS v4
- **데이터베이스**: Supabase (PostgreSQL 15+)
- **상태 관리**: Zustand (클라이언트 오프라인 큐) + TanStack Query (서버 캐시)
- **하드웨어 연동**: Bluetooth HID 키보드 웨지 이벤트 전역 리스너 + 모바일 카메라

## 3. 세부 단계별 구현 계획

### Step 1: 데이터베이스 DDL 및 시드 스크립트 작성 (`scripts/schema.sql`)
- **9개 핵심 테이블** 정의:
  - `stores` (매장 마스터)
  - `users` (작업자/관리자 마스터, 역할: `PICKER`, `INSPECTOR`, `ADMIN`, `STORE`)
  - `locations` (창고 랙 좌표: Zone·Aisle·Bay·Level[영문 A/B/C/D]·Bin 신표준)
    - id 형식: `'A01-05-B01'`, barcode 형식: `'LOC-A0105B01'`
  - `items` (상품 마스터: SKU, UPC, 규격, 단가, ZoneType, 안전재고, 유통기한일수)
  - `inventory` (로케이션별 실시간 재고 원장: `on_hand_qty`, `allocated_qty`)
  - `orders` & `order_items` (정규화된 주문 헤더 및 상세 품목)
  - `inventory_adjustments` (재고 오차 보정 감사 로그: 이전수량, 보정수량, 차이, 사유코드, 검사자ID)
  - `cycle_count_requests` (피킹 중 `CMD-SKIP` 발생 건 긴급 실사 큐)
- 데이터 무결성 제약조건:
  - `chk_positive_stock CHECK (on_hand_qty >= 0)`
  - `chk_allocated CHECK (allocated_qty >= 0 AND allocated_qty <= on_hand_qty)`
  - `chk_reason_code CHECK (reason_code IN ('COUNT_MISMATCH','DAMAGED','LOST','FOUND','EXPIRED'))`
- 테스트용 현장 시드 데이터:
  - 상온 랙 `A01-05-B01`, 냉동 랙 `F01-01-A01`, 사과/바나나 SKU, 검사자 계정

### Step 2: Next.js 프로젝트 뼈대 및 공통 라이브러리 셋업
- `package.json`, `tsconfig.json`, `next.config.ts`, `tailwind.config.ts` 설정
- **타입 정의 (`src/types/`)**:
  - `User`, `Role`, `Location`, `Item`, `Inventory`, `InventoryAdjustment`, `CycleCountRequest`
- **공통 유틸리티 & 디바이스 엔진 (`src/lib/`)**:
  - `lib/supabase.ts`: Supabase 클라이언트 싱글톤
  - `lib/audio.ts`: Web Audio API 기반 성공 비프(1200Hz) 및 경고 버저(400Hz) 사운드 엔진
  - `lib/haptic.ts`: Navigator.vibrate 기반 햅틱 패턴 엔진
- **전역 바코드 리스너 훅 (`src/hooks/use-barcode-scanner.ts`)**:
  - 블루투스 링 스캐너(HID) 연속 키입력 및 Enter 종단 감지

---

### Step 3: 백엔드 서비스 레이어 (`src/services/`)
- `src/services/inventory.service.ts`:
  - `lookupByLocation(barcode)`: 로케이션 스캔 시 적치 상품 및 수량 반환
  - `lookupByItem(barcodeOrSku)`: 상품 스캔 시 적치된 로케이션 목록 반환
  - `adjustInventoryStock(params)`: 단일 PostgreSQL 트랜잭션으로 원장 갱신 + 감사 로그 인서트
  - `transferInventoryStock(params)`: 로케이션 간 재고 이동 원자적 트랜잭션
  - `getPendingCycleCountQueue()`: 긴급 실사 큐 조회
- `src/services/auth.service.ts`:
  - 작업자 세션 검증 및 권한(`PICKER` vs `INSPECTOR`) 판별

---

### Step 4: API Route Handlers (`src/app/api/inventory/`)
- `GET /api/inventory/lookup`: 바코드 퀵 조회 (type: location / item)
- `POST /api/inventory/adjust`: 실사 보정 확정 (트랜잭션)
- `POST /api/inventory/transfer`: 로케이션 간 재고 이동
- `GET /api/inventory/cycle-count/queue`: 실사 대기 목록 반환

---

### Step 5: 프론트엔드 UI 컴포넌트 & 페이지 (`src/app/(inventory)/`)
- `src/middleware.ts`: 역할 기반 자동 라우팅 및 보안 차단
- **UI 컴포넌트 (`src/components/`)**:
  - `components/features/inventory/scanner-status-badge.tsx`: 링스캐너 연결 상태 뱃지
  - `components/features/inventory/inline-number-pad.tsx`: 한 손 Thumb-Zone 증감 패드 (`-10`, `-1`, `+1`, `+10`)
  - `components/features/inventory/location-item-card.tsx`: 로케이션 적치 상품 카드
  - `components/features/inventory/cycle-count-modal.tsx`: 실사 사유 선택 다이얼로그
- **화면 구현**:
  - `src/app/(inventory)/layout.tsx`: 상단 스캐너 상태 헤더 + 하단 엄지 네비게이션 4대 탭바
  - `src/app/(inventory)/page.tsx`: 현장 재고 메인 대시보드 [탭 1]
  - `src/app/(inventory)/lookup/page.tsx`: 퀵 바코드 조회 화면 [탭 2]
  - `src/app/(inventory)/queue/page.tsx`: 실사 큐 (긴급 URGENT / 정기 NORMAL 목록) [탭 3]
  - `src/app/(inventory)/count/page.tsx`: 전산 vs 실물 대조 실사 화면 (One-Tap 일치 지원)
  - `src/app/(inventory)/transfer/page.tsx`: 로케이션 이동 마법사 화면 [탭 4]

## 4. 품질 검증 및 아키텍처 가드레일 (QA)

1. **아키텍처 자동 검증 스크립트 통과**:
   - `powershell -ExecutionPolicy Bypass -File scripts/validate-arch.ps1`
   - Client Component에서 직접 DB 호출 금지, Secret 노출 금지, `any` 타입 사용 금지 검증.
2. **현장 시나리오 검증**:
   - 바코드 퀵 조회 시 정확한 가용재고(`on_hand - allocated`) 계산 여부.
   - One-Tap 전산 일치 시 0.1초 이내 확정 및 성공 비프음 출력.
   - 수량 오차 발생 시 사유 코드 필수 입력 및 `inventory_adjustments` 로그 기록 여부.
   - 마이너스 재고 및 피킹 할당량 미만 보정 시 트랜잭션 롤백 및 에러 처리 검증.
